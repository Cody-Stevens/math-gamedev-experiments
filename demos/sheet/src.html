Only one of the nine is a real speedup: the Snaky certificate replaces a 4.7 ms search with a 1 µs lookup. The others buy a guarantee, an exact target or a warning, and several cost more compute than the baseline. The HUD in each video shows each side's own measured compute time; rendering and encoding are excluded.

 1. Snaky: an opponent that provably wins
Speed + proof

Maker needs to claim a six-cell Snaky shape on a 17×17 board while Breaker blocks. Left is a classic α-β game AI. Right follows the paper's 39 KB certificate, which the demo rebuilds byte-identically (728 cards, hashes match the paper).

41 → 100%
Wins vs the α-β search Breaker (100 games each)
4.7 ms → 1 µs
Decision time per Maker move
≤ 21
Proved max Maker moves; a certificate-aware Breaker forces exactly 21

Game use: a certificate turns a hard search into a table walk, so "unbeatable" AI costs nothing at runtime. The same idea fits any small game you can solve offline.

Compute per frame: __C_03-snaky__ (the two sides make different numbers of decisions per frame, so compare per move).
Caveat: the certificate needs 94 KB in memory against 62 KB for the baseline. The win rate shown live in the video counts only finished games, so use the batch numbers above.
Paper: family 187, preprints/Snaky-in-21-Maker-moves-September-25-2026 · demo demos\03-snaky

 2. A crafting economy that can't collapse
Guarantee

Five resources (ore, wood, tools, food, workers) and nine recipes, run as a mass-action reaction network. Left drops two "return" recipes. Right keeps every recipe on a directed cycle (weak reversibility), and the theorem then says every resource stays between fixed positive bounds.

6/30 → 0
Resource tracks that went extinct (<1e-6)
6/6 → 0
Runs that blew up past 1e10
0.48–1.54
Range of every resource at the end, with the rule

Game use: a design rule you can check in code (strongly connected components of the recipe graph) before you ever balance a number. The demo's network sits outside every older special case, which the code also checks.

Compute per frame: __C_01-economy__ (left is slower only because its blow-up is stiff).
Caveat: the theorem proves the bounds exist but doesn't give their values, so the band in the plot is empirical. The left side's collapse is one demonstrated case, not a theorem about every network.
Paper: family 149, preprints/Uniform-Permanence-in-Weakly-Reversible-Mass-Action-Systems-October-5-2026 · demo demos\01-economy

 3. Fluid gates: swap regions without merging them
Guarantee

Three dye regions swap and reshape through overlapping slots, then return. Left tweens them in one plane: a straight lerp, then exponential scaling, which keeps area. Right uses the paper's seven-stage divergence-free shear flow, lifting each region to its own height.

105% → 0%
Overlap between regions on the same layer
33% → 5e-12
Area drift (lerp); exp-scaling also keeps area but still collides
1.90h ≤ 2h
Largest excursion, inside the proved bound

Game use: scripted fluid or crowd "gates" that move and reshape whole regions while keeping volume exact and paths separate. Good for puzzle mechanics and set pieces.

Compute per frame: __C_02-fluid-gates__ (12 threads; the new method is about 3× slower).
Caveat: this demonstrates the construction. It is not a Navier–Stokes solver benchmark.
Paper: family 376, preprints/Finite-Instructions-and-Solenoidal-Shear-Flows-September-27-2026 · demo demos\02-fluid-gates

 4. Periodic blob: the exact shape a solver should find
Exact target

In a wrap-around cube, the least-surface shape holding a given volume is a ball, then a tube, then a slab, switching at 4π/81 and 1/π. Left relaxes random starts with a standard volume-preserving MBO solver. Right draws the shape the theorem proves optimal, in closed form.

8.7% → 0.13%
Mean area above the optimum (0.13% is estimator bias)
40% → 100%
Frames showing the right shape type
20/36
Random starts within 2% after 240 solver iterations

Game use: a free, exact answer for blob, terrain and slime shapes in tiling worlds, and a test oracle that shows when your relaxation solver gets stuck.

Compute per frame: __C_07-periodic-blob__ (formula vs 3 solver iterations, so not a like-for-like speedup).
Caveat: the shapes were conjectured before; the paper proves they are the global optimum. It says nothing about relaxation speed.
Paper: family 354, preprints/The-Isoperimetric-Conjecture-for-the-Cubic-Flat-Three-Torus-September-24-2026 · demo demos\07-periodic-blob

 5. Fractal frontier: one clock for every grid size
Consistency

Critical percolation fronts creep across 64², 256² and 1024² grids. Left charges a constant speed per unit length, so finer grids take far longer. Right charges δ^(7/4) per step with one constant, which the paper proves converges.

7.9× → 0.99×
Median duration, 1024² vs 64²
683% → 2.9%
Mismatch in time spent per screen region
3.08 / 3.06 / 3.03 s
Median duration on the three grids, with the new clock

Game use: fog-of-war, fire or infection fronts that take the same time at any map resolution or LOD.

Compute per frame: __C_04-fractal-frontier__ (identical work on both sides).
Caveat: the 7/4 exponent is classical. What's new is the proof that it gives a resolution-independent measure on the square lattice. The 1-second unit is arbitrary because the paper's constant isn't known.
Paper: family 223, preprints/Natural-Occupation-Measures-for-Critical-Square-Lattice-FK-Interfaces-October-5-2026 · demo demos\04-fractal-frontier

 6. Dungeon shuffle: provably fair random layouts
Guarantee

Rewire a 20-room dungeon while every room keeps its door count. Left uses double-edge swaps with an ad hoc burn-in of one swap per door. Right uses Curveball trades for the burn-in the paper certifies: 12,644 trades.

0.46 → 1.8e-14
Exact bias (TV distance), irregular 8-room case
9.8 → 5.6
Original doors kept per layout (uniform ≈ 5.64)
0.34 ms
Cost per certified layout (about 128× the ad hoc one)

Game use: fair procedural levels for any door-count sequence, with a burn-in you can compute instead of guess.

Compute per frame: __C_06-dungeon-shuffle__.
Caveat: double-edge swaps also mix fast on these cases; they just come with no guarantee. The bound certifies fairness, not speed.
Paper: family 131, preprints/Polynomial-Mixing-of-the-Switch-Chain-for-Every-Graphical-Degree-Sequence-September-25-2026 · demo demos\06-dungeon-shuffle

 7. Convex morph: a tighter in-between with a volume floor
Guarantee

Morph between symmetric 3D crystals. Left is Minkowski interpolation, which already has a volume floor. Right is the logarithmic morph, whose floor ≥ |K|^(1−λ)|L|^λ is the new theorem. A naive vertex lerp, plotted in grey, has no floor at all.

1.65× → 1.38×
Peak bloat above the floor
≥ 1.02
Lowest volume/floor with the log morph
0.80×
Naive vertex lerp dips below the floor

Game use: morphing rooms, crystals or collision hulls that never collapse and stay closer to the endpoints than Minkowski blending.

Compute per frame: __C_08-convex-morph__ (the log body is cheaper only because fewer planes cut it; that isn't the result).
Caveat: the baseline doesn't collapse either. The gain is a smaller, guaranteed morph.
Paper: family 091, preprints/The-logarithmic-Brunn-Minkowski-conjecture-September-23-2026 · demo demos\08-convex-morph

 8. Crowd hub: a small move reshuffles many people
Warning

176,400 agents split optimally between three destinations. A hub nudges back and forth. Left keeps everyone's assignment frozen. Right recomputes the optimal assignment, which jumps like the cube root of the move. The paper proves 1/3 is sharp.

0% → 11%
Agents relabelled per nudge (largest hub)
1.00 → 0.334
Log-log slope of map change vs move (proved: 1/3)
a²/12
Exact extra cost of keeping labels frozen

Game use: if you re-solve crowd or unit allocation every frame, expect visible flicker when targets move slightly. Freezing or hysteresis is cheap by comparison.

Compute per frame: __C_05-crowd-hub__.
Caveat: this is a warning, not a faster allocator. A classical power-cell solver gives the same labels.
Paper: family 374, preprints/Sharp-One-Third-Stability-of-Brenier-Maps-September-25-2026 · demo demos\05-crowd-hub

Proved bias

Phasor walks of e^(2πi x³/p) for primes p ≡ 1 mod 3, summed into a running total M(X). Left assumes each sum is a random arrow, which is what a designer would guess. Right shows the true sums tracking the paper's proved law K·X^(5/6)/log X.

18σ

1.07
